# Fabririo

**Go-код как живая фабрика.** Локальный анализатор одного или нескольких Go-модулей с интерактивной картой в духе автоматизированного производства.

- Значения SSA и их зависимости → грузы и конвейеры.
- Функции и методы → отдельные цеха; операции → станки. Цвет корпуса и фундамента зависит от вызываемого метода, у остальных операций — от их функции.
- `chan`, отправка, получение, `select` → станции и поезда.
- Записи в БД → склады.
- HTTP, gRPC, WebRTC, WebSocket → ракетные площадки.
- `delete` и завершение использования значений → мусорки.

Это рабочий **статический обозреватель потоков**, а не профилировщик. Грузы анимируются для объяснения связей: приложение не исполняет исследуемый код, не знает реальные значения, частоту вызовов, выбранную ветвь, расписание горутин или момент GC.

## Запуск

Нужен **Go 1.25+**; для анализа проекта с более новой версией языка нужен соответствующий установленный Go. Node.js, npm, игровые движки и внешние сервисы для работы приложения не нужны.

```bash
./start.sh
```

Откройте **http://127.0.0.1:8080**. Без аргументов загружается встроенная демофабрика: два настоящих Go-модуля `forge.local/dispatch` и `forge.local/ledger`. Она анализируется тем же SSA-анализатором, что и пользовательский код. Демонстрационные адаптеры gRPC/WebRTC/WebSocket помечены аннотациями; HTTP и SQL распознаются по настоящим вызовам стандартной библиотеки. Код демонстрации не выполняется.

Можно запустить через Go напрямую:

```bash
go run ./cmd/fabririo

# Один модуль
go run ./cmd/fabririo -project /absolute/path/backend

# Несколько связанных модулей: их локальные версии будут связаны по module path
go run ./cmd/fabririo \
  -project /absolute/path/service \
  -project /absolute/path/shared \
  -listen 127.0.0.1:8081

# Build tags и экспорт для других инструментов
go run ./cmd/fabririo -project /absolute/path/backend -tags integration -json factory.json

# Количество модулей по умолчанию не ограничено (0).
# При необходимости задайте предел для CLI и всех последующих загрузок в браузере.
go run ./cmd/fabririo -max-modules 128
./start.sh -max-modules 0
```

В интерфейсе кнопка **«Подключить проект»** принимает пути к папкам с `go.mod`, по одному на строку. Можно анализировать разные проекты по очереди без перезапуска сервера.

Перед анализом стороннего проекта его зависимости должны находиться в локальном кэше Go. Если их нет, выполните `go mod download` в самом проекте. Первоначальная сборка Fabririo также загружает его обычные Go-зависимости.

## Управление фабрикой

- Перетаскивание блока левой кнопкой меняет его положение с привязкой к сетке. После отпускания ленты и рельсы перестраиваются; остальные блоки сохраняют свои координаты. Занятое место или невозможность построить маршруты отменяют перенос. **Esc** отменяет перенос до отпускания.
- Перетаскивание пустого места, **Shift + перетаскивание** или средняя кнопка двигают карту; колесо — масштабирование вокруг курсора.
- Фабрика, раскладки посещённых цехов/участков, камера, слои, выбранный объект и параметры анимации автоматически сохраняются в IndexedDB. При перезапуске страницы или сервера восстанавливается последний снимок. Хранилище привязано к браузеру и адресу (включая порт); статус сохранения показан внизу. Повторный анализ через «Подключить проект» или «Открыть демофабрику» создаёт новую раскладку.
- **Пробел** — пауза; кнопка скорости — от 0.25× до 4×; **F** — вписать карту целиком.
- Навигатор слева — отдельные функции и весь проект; **/** — поиск функций, типов и имён переменных.
- **«Фабрика»** скрывает промежуточные преобразования и сворачивает соседние цеха в здания со стрелкой `↗`. Нажатие открывает соответствующий цех.
- **«Все операции SSA»** показывает промежуточные операции без сворачивания.
- Нажмите на станок или выберите его в списке инспектора: справа появятся тип, операция SSA и строки Go-кода.
- **«Проследить груз»** подсвечивает предшествующие и последующие связи выбранного объекта.
- Стрелка возле исходника открывает файл целиком с выделением строки.
- Переключатели слоёв скрывают типы объектов и маршрутов. Миникарта позволяет переходить между участками.
- **«Экспорт» → GIF** сохраняет анимацию текущего вида карты или всей построенной фабрики/участка. Доступны 3/6/10 секунд, 10/20 кадров/с и стандартные кадры 720p (1280 × 720), 1080p (1920 × 1080), 2K/QHD (2560 × 1440), 4K (3840 × 2160). Текущий вид вписывается в кадр 16:9 с полями без растягивания или обрезки; вся построенная фабрика вписывается целиком. Также доступны компактные 640/960 пикселей по длинной стороне. Цвета, формы, скорость и подсветка сохраняются; пауза карты не останавливает экспорт. GIF повторяется по кругу; место склейки зависит от движения на выбранных маршрутах. Для большого проекта это выбранный участок или обзор пакетов.
- **«Экспорт» → CSV** сохраняет объекты (`record=node`) и связи (`record=edge`) в один файл UTF-8 с BOM. Можно выбрать построенную фабрику с координатами, длинами, геометрией маршрутов и мостами либо полный SSA-граф без раскладки. Разделитель — запятая или точка с запятой; массивы хранятся как JSON внутри ячеек, кавычки и переносы строк экранируются. Текст, похожий на формулу таблицы, получает начальный апостроф. Координаты и размеры — в пикселях мира, `length_tiles` — в тайлах.
- **«Экспорт» → JSON** сохраняет переносимый снимок `fabririo-factory` версии 1: полный граф, содержимое исходников, все посещённые раскладки с точными координатами и маршрутами, выбранный цех/участок, поиск, слои, камеру, выделение, подсветку, скорость и паузу. Исходники и литералы входят в файл.
- **«Импорт JSON»** восстанавливает снимок без повторного анализа Go и доступа к оригинальным папкам. Импорт проверяет структуру, ссылки, координаты и геометрию всех сохранённых маршрутов до замены текущей фабрики. Повреждённый или неподдерживаемый файл оставляет текущую фабрику на месте. Максимальный размер файла — 64 МиБ. Принимается и старый JSON полного графа (включая CLI `-json`): для него строится новая раскладка, исходники недоступны. CLI `-json` по-прежнему экспортирует только граф.

GIF и CSV создаются локально в браузере, в отдельном worker с прогрессом и отменой. Для GIF нужен OffscreenCanvas; сырые кадры обрабатываются по одному. Неизменившиеся части кадров GIF сохраняются через прозрачные области, чтобы большие анимации занимали меньше места. Максимальный размер GIF — 64 МиБ; при превышении можно уменьшить длительность или разрешение.

Тип Go задаёт цвет груза, а семейство типа — его форму: числа, строки, логические значения, указатели, срезы, массивы, map, каналы и другие типы различимы по силуэту. Вагоны используют те же формы и цвета. Конвейер и его мост окрашены в цвет перевозимого типа; после слияния разных типов лента становится полосатой, сохраняя цвета всех грузов. Легенда «Типы грузов» справа показывает типы текущей линии. Цвета стабильны при переключении функций, участков и режима SSA.

Маршруты прокладываются по сетке 32 × 32 пикселя. Если свободные порты зданий находятся на одной линии, конвейер или рельсы идут прямо, включая короткие соединения из двух тайлов. Подходы двух концов одного маршрута могут совпадать; подходы чужих маршрутов остаются препятствиями. Неподвижные контрастные стрелки повторяются по всей длине лент, включая мосты, и показывают направление от источника к получателю на скриншотах и в GIF. На земле ленты занимают разные тайлы и обходят здания. Для пересечения другой ленты или железной дороги строится мост с въездами, поднятой лентой и ограждениями. Мосты, включая въезды, не пересекаются и не касаются друг друга. Утилизация занимает **ровно один тайл**, включая область выбора мышью; несколько входящих лент соединяются через отдельные узлы сбора.

Каналы имеют непрерывные пути с двумя рельсами, шпалами и плавными поворотами. По ним ездят локомотивы с вагонами: состав останавливается у концов пути и возвращается задним ходом, сохраняя порядок вагонов. Раскладка выполняется в фоновом потоке; выбор другого цеха отменяет предыдущий расчёт. Если в плотном графе не удаётся проложить все пути после расширения карты и повторной раскладки, интерфейс сообщает об этом и предлагает выбрать отдельный цех — пересекающиеся ленты вместо маршрутов не рисуются.

При построении используется **граф зависимостей**: у объекта есть непосредственные соседи по входящим и исходящим связям, затем соседи этих соседей. Каждая связанная группа начинается с объекта с наибольшим числом соседей. Связанные объекты притягиваются друг к другу, повторные связи усиливают притяжение, а объекты с большим числом зависимостей стремятся ближе к центру группы. Непосредственное соседство получает отдельный приоритет. При перемещении проверяются свободные места возле всех зависимостей, включая перенос через промежуточные блоки и обмен местами; позиции остаются на сетке без наложения зданий. Узлы сбора и деления участвуют в размещении, при этом исходные зависимости станка сохраняют свой вес. Между цехами применяется тот же принцип, а несвязанные группы размещаются отдельно. Порядок операций SSA больше не задаёт колонки фабрики.

Кнопка **«Перестроить по связям»** применяет раскладку к текущему виду, в том числе восстановленному из автосохранения или JSON. Она заново размещает и вручную перемещённые блоки. Новая раскладка сохраняется только после успешного построения; при ошибке остаётся предыдущая.

После начальной оптимизации выполняется **сборка составных объектов по связям**. Сначала выбирается объект с одной внешней связью и присоединяется к своему соседу; для соединения ищется короткий прямой путь. Затем рассматриваются объекты с двумя, тремя и большим числом связей. После каждого объединения число внешних связей пересчитывается: новая группа сама может стать объектом с одной связью. Если соседей несколько, первым выбирается тот, с которым больше общих связей. Входящие и исходящие связи учитываются одинаково, параллельные маршруты — отдельно, а связи внутри группы больше не влияют на её приоритет.

Группа хранит входящие в неё блоки и внутренние маршруты. При следующем присоединении переносится вся группа одним смещением, включая конвейеры и рельсы; заново прокладываются только внешние связи. Уже собранные части не разбираются и не деформируются. Процесс заканчивается отдельной группой для каждой связной части фабрики; циклы и несвязанные объекты также поддерживаются. Если препятствия или занятые порты не позволяют улучшить соединение, сохраняется действующий маршрут. Иерархия объединений входит в автосохранение и JSON. **Мышью перемещается только выбранный блок**: ручной перенос освобождает раскладку от автоматических групп, остальные здания остаются на своих местах.

Перед объединением в составные объекты выполняется **начальная оптимизация фабрики**. Длинные пути становятся поводом передвинуть связанный блок на свободное место рядом с его соседом: при этом перестраиваются все входящие и исходящие связи блока, а остальные маршруты остаются препятствиями. Перенос принимается только после проверки всей геометрии и улучшения фактической длины путей, площади или числа мостов без ухудшения остальных показателей. Число попыток ограничено, поэтому соседство — приоритет, а не гарантия для любого плотного графа. Оптимизация удаляет свободные полосы между зданиями и поперечными маршрутами, сокращает прямые участки конвейеров и рельсов, затем ищет более короткие пути для 12 самых длинных обходов. Мосты, под которыми больше нет транспорта, заменяются наземной лентой. После этого карта уплотняется ещё раз. Размер зданий, все связи, въезды на мосты и подходы к станциям сохраняются; расстояния для анимации пересчитываются по новым путям.

В самом конце, после всех объединений и переносов групп, выполняется **повторная оптимизация длин маршрутов**. Она проверяет оставшиеся обходы конвейеров и рельсов, включая внутренние маршруты собранных групп, с фиксированными зданиями и портами. Поиск повторяется до отсутствия улучшений, максимум три прохода: сокращение одного пути может освободить более короткий проход для другого. Каждый принятый вариант сохраняет все связи и проходит проверку геометрии; неиспользуемые мосты убираются. Итоговые показатели включают этот этап, а подсказка под заголовком показывает длину путей до и после финального сокращения.

Каждый вариант проверяется целиком: площадь занятой территории, суммарная длина путей и число мостов не должны увеличиваться, пересечения запрещены. Неудачная попытка оставляет последнюю рабочую раскладку. Это ограниченный поиск улучшений, а не гарантия глобально минимального завода. Под названием цеха показывается фактическое сокращение площади и длины маршрутов; при наведении — значения до и после в тайлах. Оптимизация работает в том же фоновом потоке и отменяется при переключении цеха или фильтра.

Для крупных проектов (более 1200 объектов SSA) начальная карта показывает пакеты и суммарные связи между ними. Нажатие на пакет открывает каталог функций; функцию также можно выбрать в навигаторе или через поиск. Анализ и JSON-экспорт содержат **весь граф**.

Если в функции больше 48 отображаемых операций, её карта разбивается на участки по 24 операции. Кнопки под заголовком и переходы `↗` открывают соседние участки или их каталог. Входящие и исходящие связи сохраняются; параллельные связи с внешним участком объединяются в переход с полным списком исходных связей. Для очень больших функций переходы группируются во вход и выход других участков. Режим SSA позволяет исследовать промежуточные операции тем же способом.

## Что анализируется

Fabririo загружает типизированные пакеты через [`go/packages`](https://pkg.go.dev/golang.org/x/tools/go/packages) и строит [`go/ssa`](https://pkg.go.dev/golang.org/x/tools/go/ssa) с отладочными привязками к исходным переменным. Каждое SSA-значение имеет отдельный идентификатор; несколько исходных имён могут обозначать одно и то же значение, например при `b := a`.

Анализ включает функции, приватные методы, инициализацию глобальных переменных, замыкания, instantiated generic-функции, объединения значений в ветвях и циклах (`phi`), прямые вызовы, аргументы, возвраты, чтение и запись памяти. Загружаются файлы текущих GOOS/GOARCH и выбранных build tags; `_test.go` не включаются. Зависимости за пределами выбранных модулей остаются внешними операциями, их внутренние тела не разворачиваются.

Для нескольких модулей создаётся временный `go.work`. Входные `go.mod`, `go.sum`, `go.work` не изменяются. Исследуемая программа, её тесты и `go generate` не запускаются; `go/packages` вызывает установленный Go для загрузки пакетов и типов. Автоматическая загрузка зависимостей и toolchain при анализе отключена. Go может использовать свой кэш компиляции.

Связи каналов определяются по SSA-идентичности, а не по имени `queue`: передача в параметры функций, возвращаемые каналы, захваты замыканий, глобальные каналы и прямые преобразования направления учитываются. Возможные отправители и получатели объединяются в маршруты поездов.

### Склады и ракеты

Распознавание использует пакет и тип вызываемой функции/метода:

- `database/sql`, `sqlx`, `pgx`: `Exec`, `ExecContext`, `CopyFrom`, `SendBatch`; также `Query*` с литералом SQL, начинающимся с записывающего оператора, например `INSERT … RETURNING`.
- GORM, MongoDB и go-redis: распространённые методы изменения данных.
- `net/http`: клиентские отправки и методы `ResponseWriter`.
- gRPC: `Invoke`, `SendMsg`, создание потоков и клиентские методы с `grpc.CallOption`.
- Gorilla/coder/nhooyr/x/net WebSocket: методы отправки и записи.
- Pion WebRTC: `Send`, `SendText`, `WriteRTP`, `WriteRTCP`, `WriteSample`.

Для собственного адаптера добавьте комментарий непосредственно перед его объявлением:

```go
//fabririo:rocket webrtc
func SendToPeer(payload []byte) error {
    // ...
    return nil
}

//fabririo:warehouse postgres
func SaveOrder(order Order) error {
    // ...
    return nil
}

//fabririo:trash
func Discard(buffer []byte) {
    // ...
}
```

Инспектор указывает основание классификации: конкретный API или явную аннотацию. Одна лишь переменная с именем `db`/`http`/`websocket` не создаёт склад или ракету.

### Границы точности

- Это граф возможных зависимостей, без динамических значений и гарантии выполнимости каждого маршрута. Пути ветвей и итерации циклов не симулируются как реальное выполнение.
- Вызовы через интерфейсы и переменные-функции могут остаться внешними станками. Полного whole-program pointer analysis нет.
- Межпроцедурное сопоставление аргументов контекстно-независимо: если одну функцию вызывают с разными каналами, возможны дополнительные маршруты между её вызывающими сторонами. Каналы внутри `map`, `slice`, сложных структур и многоступенчатых алиасов могут остаться несвязанными.
- Записи/чтения по известным адресам связаны консервативно; значения из разных ветвей не исключаются. Не все побочные эффекты внешних функций известны.
- Мусорка завершения использования — условная граница жизни SSA-значения. Копия значения, владение указателем и освобождение памяти сборщиком мусора — разные вещи; этот режим не измеряет GC.
- SQL, собранный динамически, пользовательские обёртки и нестандартные протоколы требуют аннотации. `Exec` классифицируется как запись, но фактический SQL может иметь другую семантику.
- Код должен проходить загрузку Go-типов. При ошибке показывается диагностика, предыдущая фабрика сохраняется.
- Количество модулей по умолчанию не ограничено. Флаг `-max-modules N` задаёт предел для CLI и подключений через веб-интерфейс; `0` отключает его, отрицательные значения отклоняются. Повторяющиеся пути и симлинки на один корень считаются одним модулем.
- Размер графа по умолчанию не ограничен. При необходимости задайте `-max-nodes N` и `-max-edges N`; эти ограничения действуют для CLI и веб-интерфейса, `0` отключает их. Ошибка указывает достигнутый размер и нужный флаг. Размер исходника для просмотра ограничен 2 МиБ на файл.

## Сборка и проверки

```bash
make build
./bin/fabririo -project /absolute/path/backend

go test ./...
go test -race ./...
go vet ./...

# Необязательно: тесты модели интерфейса, нужен Node.js 20+
node --test tests/*.test.js
```

HTML/CSS/JavaScript и демо встроены в Go-бинарник через `embed`. Для разработки интерфейса пересоберите/перезапустите сервер и обновите страницу: hot reload не используется.

Тесты покрывают связи модулей, идентичность каналов, замыкания, global init, generics, приватные методы, `phi`, `delete`, build tags, SQL `RETURNING`, ошибки типов, детерминизм графа, отмену загрузки, снимки исходников, HTTP-ограничения, сворачивание графа, отсутствие пересечений лент и мостов, размер утилизатора и непрерывное движение вагонов. Геометрия проверяется на всех цехах встроенного демо в обоих режимах, включая общий граф.

## Структура

```text
cmd/fabririo/           CLI и запуск локального сервера
internal/analyzer/     Загрузка Go, построение графа, классификация API
internal/graph/        JSON-модель фабрики
internal/demo/         Встроенные исходники двух демонстрационных модулей
internal/web/          HTTP API, снимки исходников, embed
internal/web/static/   Canvas 2D, граф/раскладка, интерфейс
tests/                 Тесты JavaScript-модели
```

Сервер слушает только loopback-адреса и проверяет Host/Origin. Исходники выдаются из снимка по идентификатору файла, а не через произвольное чтение путей. Это однопользовательское локальное приложение; не выставляйте его наружу через reverse proxy.
